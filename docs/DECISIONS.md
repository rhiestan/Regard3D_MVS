# Design and IP decision log

Every design decision with IP, licensing or architectural impact is recorded here with its date, so that
the origin of each technique can be traced later. Algorithms are implemented clean-room from the
published papers listed in the project plan (§1, kept outside this repository); no code is copied from patented or copyleft implementations.

*Not legal advice. Items marked OPEN must be checked against actual patent claims before the related
code is released.*

## Decisions

| # | Date | Decision | Rationale / source |
|---|---|---|---|
| D1 | 2026-10-24 | Primary matcher: pairwise rectified hierarchical Census-SGM followed by multi-stereo triangulation. Reference-view plane sweep is the secondary/fallback matcher. | Hirschmüller, TPAMI 2008 §2.4 (cost-level multi-view fusion is unstable under occlusion); Wenzel et al., ISPRS 2012 (SURE architecture); Hirschmüller & Scharstein, TPAMI 2009 (Census most robust). |
| D2 | 2026-10-24, rev. 2026-10-25 | OpenMVG scenes are read by our own parsers, with no link dependency on OpenMVG or cereal: `sfm_data.json` (nlohmann/json, landmarks streamed through a parser callback) and `sfm_data.bin` (own decoder of cereal's portable binary archive). Versions 0.1-0.3, `view_priors`, all perspective camera models; spherical cameras are read and their views skipped. | Light dependency footprint; decided by the project owner. `.bin` added on 2026-10-25 (owner's request): it is what Regard3D writes, and the JSON is about 10x larger and 70x slower to parse (Luzern: 52 MB / 0.08 s vs. 533 MB / 6 s). |
| D3 | 2026-10-24 | No built-in mesher. Output is a dense point cloud with normals, scale, confidence and optional visibility, for PoissonRecon / FSSR / texrecon. Revisit only if the Phase 7 benchmark shows meshing is the bottleneck. | Decided by the project owner; see the project plan §3.9. |
| D4 | 2026-10-24 | Third-party code is fetched with CMake FetchContent, pinned to exact releases and verified by SHA256; `R3D_USE_SYSTEM_DEPS=ON` prefers installed packages. Header-only libraries are wrapped without running their CMake scripts. | Reproducible builds without requiring vcpkg/Conan; works identically on all CI platforms. |
| D5 | 2026-10-24 | Own thread pool (`r3d::ThreadPool`) instead of oneTBB for now. Chunk boundaries depend only on the range and grain, never on the thread count, and nested `parallel_for` runs serially. | Deterministic results, no extra binary dependency. Revisit (oneTBB, Apache-2.0) if load balancing of nested/irregular work becomes a bottleneck. |
| D6 | 2026-10-24 | Image decoding via stb_image (JPEG, PNG 8/16-bit, PNM, BMP, TGA); own PNG encoder (8/16-bit, adaptive filters) on stb's zlib compressor. | Zero native dependencies. Revisit in Phase 1 if JPEG decoding speed matters (libjpeg-turbo) or TIFF input is required (libtiff). |
| D7 | 2026-10-24 | C++20 with `std::format`. Minimum compilers: MSVC 19.30, GCC 13, Clang 17, AppleClang 15 (macOS deployment target 13.3). | `std::format` removes the need for fmt; these are the "recent compilers" targeted in the plan. |
| D8 | 2026-10-24 | Point positions are stored as float relative to a double-precision `origin`. PLY output writes either relative float coordinates plus an `r3d_origin` comment, or absolute doubles. | Halves memory for 100M+ point clouds while keeping sub-mm precision for georeferenced scenes. |
| D9 | 2026-10-24 | Eigen is compiled with `EIGEN_MPL2_ONLY`. | Rules out the few LGPL-licensed Eigen code paths at compile time. |
| D10 | 2026-10-24 | Pixel convention: integer pixel coordinates are pixel centres; (0, 0) is the centre of the top-left pixel (OpenMVG convention). The COLMAP importer will shift by −0.5. | Single convention throughout the code base. |
| D11 | 2026-10-24 | Highway kernels must be bit-exact with their scalar reference; tests run every compiled and supported target (`ScopedSimdTarget`). | Deterministic output across machines, and SIMD bugs are caught on every CI platform. |
| D12 | 2026-10-25 | Unit tests use doctest (single header, MIT) instead of Catch2. Own `main` routes MSVC CRT assertion reports to stderr; every CTest test has a 300 s timeout. | Decided by the project owner. Fast to compile, thread-safe assertions; the CRT change fixes a Debug run that blocked on an assertion dialog. |
| D13 | 2026-10-25 | Camera models follow OpenMVG's formulas exactly (`add_disto`), verified against values generated with OpenMVG. The inverse uses damped Newton iteration (accurate to ~1e-12) instead of OpenMVG's bisection / fixed-point iterations. COLMAP models are mapped onto the same models. | One distortion implementation for both importers; OpenMVG's fisheye inverse stops after 10 iterations and is visibly inexact near the border. |
| D14 | 2026-10-25 | Undistortion keeps the focal length and by default covers the whole source image (`keep_all`, invalid corners masked; growth per side capped at 1.5x); `inner` and `same_size` are options. Resampling is bicubic (Catmull-Rom); the distortion is evaluated per output pixel instead of storing maps. A folding distortion (non-positive Jacobian inside the image) is detected and reported. | No source pixel is lost for matching; constant resolution at the image centre. Maps would cost 8 bytes per pixel and camera. Measured: features land within 0.01 px of their pinhole positions. |
| D15 | 2026-10-25 | Pyramids: binomial [1 4 6 4 1]/16 filter, then every second pixel, so pixel i of level k+1 is centred on pixel 2i of level k and the level-k camera is K / 2^k (no half-pixel offset). Integer images are rounded exactly. | Simplest exact geometry for coarse-to-fine matching. |
| D16 | 2026-10-25 | View selection per base view from the SfM tracks: per shared point the weight max_a Gauss(angle; a in {10, 20} deg, sigma 10 deg), zero outside [3, 45] deg, times Goesele's scale weight; pair score = weight sum / points of the base view x coverage (8x8 grid). Greedy choice of up to 4 partners with a penalty for similar baseline directions in the base image. Pairs with a GSD ratio above 2 are rejected; forward motion (epipole in the image) is flagged for the rectification stage. | Goesele et al. 2007 and Wenzel et al. 2014; O(1) memory per view pair. |
| D17 | 2026-10-25 | Optional integration tests run on real scenes from `R3D_TESTDATA_DIR` (default `../testdata`, outside the repository); they are compiled only if the directory exists, so CI runs the synthetic tests only. | Copyrighted / large test images stay out of the repository. |
| D18 | 2026-10-25 | Rectification: calibrated, own implementation of Fusiello, Trucco & Verri (2000) with the mean of both optical axes as viewing direction. The base view is always the left image, at its own focal length. Both images are resampled once from the original (distorted) images; a pyramid level is used as anti-aliasing when the partner is reduced by more than 1.5x. Each rectified image is cropped to 1.5x its source half-size around its rectified principal point, and a pair is rejected only if less than 40% of either image remains (near-forward motion). The disparity range comes from the SfM depth range evaluated on rays across the base image; label counts are multiples of 16. | Single resampling keeps sub-pixel accuracy. Cropping instead of rejecting keeps the near-forward pairs that are common in walk-around captures (6 of 27 best partners in luzern_loewe); the discarded periphery near the epipole has almost no parallax. Polar rectification remains an option for pairs with the epipole inside the image. |
| D19 | 2026-10-25 | Matching cost and penalties: Census 9x7 (62 bits, bit set when the neighbour is darker), Hamming distance 0..62. P1 = 28, P2 = 200, intensity-adaptive P2' = max(P1 + 1, P2 * 4 / (4 + abs(dI))) with dI in 8-bit units. Correspondences outside the right image cost 31; masked left pixels cost 0 for all labels. | Tuned on the Middlebury 2014 training set (H and Q). Census is the most robust cost under radiometric differences (Hirschmüller & Scharstein, TPAMI 2009). |
| D20 | 2026-10-25 | SGM aggregation: 8 paths in two passes (4 paths each, fused in one row kernel), 16-bit saturating arithmetic, path buffers with sentinel labels. Matching costs are recomputed per row in both passes instead of being stored, so only the aggregated volume (2 bytes per label) is kept. Label loops use whole vectors only (full width plus a 16-lane tail), so every SIMD target is bit-exact with the scalar kernels and with a separate textbook implementation used in the tests. | Memory is the limiting resource of full-range SGM (plan section 7); the cost recomputation takes about 30% of the aggregation time. |
| D21 | 2026-10-25 | Disparity selection: winner-takes-all (first minimum), left-right check (tolerance 1 label) against the right image's WTA along the diagonal of the same volume, restricted to valid left pixels; optionally (`lr_full_match`) against a separate right-to-left match on mirrored images (about 1.75x slower, slightly better). Sub-pixel by the equiangular fit (Shimizu & Okutomi 2001), uniqueness test off by default, speckle filter (segments under 100 pixels, step 1) and a 3x3 median of the valid values. | TPAMI 2008 section 2.4. Including masked pixels in the right-image WTA invalidated whole tiles next to masked areas (found on luzern_loewe, regression test added). |
| D22 | 2026-10-25 | Tiling: independent tiles (core 512 px, discarded margin 32 px, linear blending over 32 px), as in TPAMI 2008 section 2.6, with no path costs passed between tiles. The tile layout depends only on the image size and the options (the tile size is halved until a tile fits the memory budget); the number of tiles processed at once is limited by the budget. Results are identical for every thread count. | D5 determinism. Within one pair the parallelism is limited to the tile count; the MVS pipeline (Phase 4) runs pairs in parallel. |
| D23 | 2026-10-25 | Stereo evaluation follows MiddEval3: errors in full-resolution pixels (x4 at Q, x2 at H), the official scene weights, non-occluded mask, holes filled by the SDK's background interpolation for dense scores. The reference SGM is scored by running the same evaluation on Hirschmüller's published MiddEval3 outputs. | Comparable numbers without the SDK. Middlebury's own table uses its upsampling to full resolution, so its numbers differ slightly from ours for the same output. |

## Avoided techniques (from the earlier design review, `input.txt`)

| Technique | Status |
|---|---|
| eSGM-style storage of per-direction minima only | Avoided: the full aggregated cost volume of each tile is stored. |
| Cost compression / disparity sub-sampling of path costs | Avoided: full label resolution, `uint16` aggregated costs. |
| Tiling that passes boundary path costs between tiles | Avoided: independent overlapping tiles with blending (TPAMI 2008 §2.6). |
| Non-uniform disparity labels | Avoided: uniform disparity (rectified) or uniform inverse depth (plane sweep). |
| PatchMatch randomised search (as in COLMAP/OpenMVS) | Avoided as the core; refinement uses deterministic least squares (Goesele et al. 2007, MPGC). |

## Resolved IP checks

| Item | Date | Result |
|---|---|---|
| OPEN-1: classic SGM (Hirschmüller, DLR) | 2026-10-25 | Published at CVPR in June 2005. Searches (Google Patents, USPTO full text) found no DLR patent on the method. Any application would have had to be filed by June 2006 at the latest (US one-year grace period), so its 20-year term would have ended by June 2026. Later SGM patents of other owners (e.g. US 11,218,699 / US 11,831,874 "SGM cost compression", US 10,080,007 "hybrid tiling for SGM hardware") claim techniques we avoid: we keep the full cost resolution and use independent tiles as published in TPAMI 2008 §2.6. Classic SGM is treated as free to use. |
| OPEN-3: Census transform | 2026-10-25 | Published by Zabih & Woodfill (ECCV 1994). The Interval Research patent US 6,215,898 (filed 1997-04-15, later assigned to TYZX / Intel) has expired (status "Expired - Lifetime", 2017-04-15). |
